# Café Lucky Wheel MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the offline Android tablet prize-wheel app described in the PRD, with the look and behaviour of the HTML prototype.

**Architecture:** Single-activity Compose app, MVVM, manual DI through an `AppContainer`. All outcome logic lives in a pure Kotlin `domain` package. Room holds prizes and DataStore holds settings and PIN state. The spin result is drawn when the spin starts. The animation is a time-based function of that plan, so it survives rotation and backgrounding. Quantity is decremented in one guarded transaction when the result is revealed.

**Tech Stack:** Kotlin (AGP 9 built-in), Jetpack Compose + Material 3, Navigation Compose 2.10, Room 2.8 (KSP 2.3), DataStore Preferences 1.2, Coil 3, SoundPool, JUnit 4, Robolectric 4.17 (JVM Room, DataStore, ViewModel and Compose UI tests).

**Spec:** `docs/PRD.md`. **Design:** `docs/Cafe Lucky Wheel (standalone).html`. It is a bundled React prototype; decode it with `python3 -I <scratch>/unbundle.py`, and `template.html` holds the markup and logic. The prototype is the source of truth for visuals, copy, theme specs, sound parameters, particle shapes and spin feel. The PRD is the source of truth for behaviour where the two differ.

## Global Constraints

- Package `io.github.alanrb.luckywheel`; minSdk 33, compile/target SDK 37; Gradle root is `android/`.
- No `INTERNET` permission, analytics or tracking SDKs.
- Use integer basis points only for weights; the total is 10,000 bp. The draw uses `SecureRandom` in production and an injectable `RandomSource`.
- All UI text is Vietnamese and lives in `res/values/strings.xml`, copied verbatim from the prototype.
- Font: Be Vietnam Pro (OFL) bundled in `res/font`, weights 400–900.
- Theme assets are drawn in code. Sounds are generated by `tools/generate_sounds.py` (stdlib synthesis that mirrors the prototype's WebAudio parameters) into `res/raw/*.wav`.
- Priorities when ambiguous: never award beyond quantity; animation and touch never influence the outcome; Settings is never shown without the PIN.
- Commit messages carry requirement IDs and have no Claude attribution or co-author trailer.

## Review Focus

1. **Rotation or backgrounding mid-spin:** the same prize is revealed exactly once and the quantity drops by exactly 1. Tests in Task 6 recreate the ViewModel from `SavedStateHandle` and call `onSpinAnimationFinished()` twice.
2. **Double tap on QUAY, or a flick during a spin:** only one plan is created and the random source is consumed once. Covered by a Task 6 test.
3. **A 24-character single word in a 12-slice wheel:** the label is ellipsized on one line inside the slice and never overflows. A Task 7 `fitLabel` test uses a fake measurer.
4. **Draft edits (add, delete or reorder, then save):** the order persists, new rows get real ids, and the fallback cannot be deleted. Covered by Task 4 and Task 9 tests.
5. **PIN lockout across an app restart:** the lock persists because it is stored. A Task 5 test rebuilds the `PinManager` over the same DataStore file.
